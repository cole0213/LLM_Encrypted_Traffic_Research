## 1. 배경 ① — LLM의 진화

- **[확인된 사실]** 최근 LLM은 최종 답변 전에 내부 "사고 단계"를 거치는 **추론형(reasoning) 모델**로 확장되었다.
  대표적으로 OpenAI o1 계열(“Learning to reason with LLMs”, OpenAI, 2024), Anthropic Claude *extended thinking*,
  OpenAI 오픈웨이트 **gpt-oss**(gpt-oss-120b/20b, Apache 2.0), DeepSeek-R1(arXiv:2501.12948)이 있다.
- **[확인된 사실]** 이 모델들은 **추론에 쓰는 계산량을 파라미터로 조절**할 수 있다.
  - OpenAI: `reasoning.effort` = low / medium / high (+일부 xhigh/max). "모델이 얼마나 생각할지" 안내(OpenAI reasoning 문서).
  - Anthropic: extended thinking의 `budget_tokens`(최소 1,024) — **단, 최신 모델에서는 deprecated되고 adaptive thinking + `effort`로 이동 중**(Anthropic 공식 문서).
  - gpt-oss: reasoning effort low/medium/high — "latency vs. performance 트레이드오프"(OpenAI GitHub/블로그).
- **[확인된 사실]** *test-time compute*(추론시간 연산)를 최적 배분하면 파라미터를 키우는 것보다 효율적일 수 있다
  — Snell et al., "Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters"(arXiv:2408.03314, 2024).
  특정 조건에서 test-time compute 효율을 4배 이상 개선하고 훨씬 큰 모델을 능가하는 사례를 보고.
- **[연구 프레이밍]** 위 흐름 + 에이전트화(스스로 생각→도구호출→관찰 반복, 한 작업에 수십~수백 요청)로
  LLM 트래픽이 양적·질적으로 급변 중이며, 이것이 새로운 관측 대상이 된다.

## 2. 배경 ② — 암호화 트래픽의 현실

- **[확인된 사실]** 거의 모든 LLM 통신은 HTTPS/TLS로 암호화되어 **내용(payload)은 관측자에게 보이지 않는다.**
- **[확인된 사실]** 그러나 TLS는 **패킷 크기·방향·타이밍·개수 같은 트래픽 '모양(shape)'은 숨기지 못한다.**
  TLS 1.3은 traffic analysis에 대한 보장을 제공하지 않으며 record padding(레코드 패딩)이라는 **부분적 완화 수단만** 규정한다
  (RFC 8446 §5.4 "Record Padding" — 확립된 사실이나 본 정리에서 원문 §5.4를 직접 재열람하지는 않음 **[미확인: 원문 직접 대조]**;
  종합 서베이 *Electronics* 13(20):4000, MDPI 2024가 동일 취지 서술).
- **[연구 프레이밍]** 이 '겉모습'만으로 암호문 안의 성격을 추론하는 것이 **side-channel(부채널)**이며, 본 연구의 출발점.

## 3. 이런 트래픽의 특성 — 무엇이 보이나

- **[확인된 사실]** 암호화 상태에서도 노출되는 것: 패킷 크기, 방향(상/하향), 타이밍, 개수.
  이 신호만으로 사용자 행동을 식별하는 연구는 웹사이트 핑거프린팅에서 오래 확립됨
  (Wang et al., USENIX Security 2014; Hayes & Danezis "k-fingerprinting", USENIX Security 2016).
- **[확인된 사실]** LLM 스트리밍 응답은 토큰 단위로 서버가 클라이언트에 내려보내는(SSE) 구조라,
  **생성 타이밍이 출력의 성격을 누출**한다. 예: 출력 토큰 수가 응답 생성 시간으로 새는 것이 실증됨
  (Zhang et al., "Time Will Tell", arXiv:2412.15431).
- **[확인된 사실 → 연구 프레이밍]** 추론형 모델은 답 전에 내부적으로 생각한다(§1).
  OpenAI o-series의 경우 **reasoning token이 API로 노출되지 않고 output 토큰으로 과금**된다(OpenAI reasoning 문서)
  → 클라이언트 관점에서는 답변 시작 전 **패킷이 없는 '침묵' 구간**이 생긴다는 것이 본 연구의 관측 가설.
  반대로 Claude extended thinking은 요약된 thinking을 **스트리밍**한다(Anthropic 문서) → 침묵이 아니라 흐름.
  **즉 '추론이 트래픽에 남기는 자국'의 형태는 provider별로 다르다** — 이 축의 체계화가 설계본의 핵심(설계 §1-A).

## 4. 기존 연구의 빈틈

선행 LLM side-channel은 '내용 근처'까지 갔으나 **'계산적 성격(얼마나 깊이 추론했나)'은 다루지 않았다.**

| 선행 연구 | 무엇을 누출/탐지 | 신호 | 출처 |
|---|---|---|---|
| Whisper Leak | 프롬프트의 **주제(topic)** | 패킷 크기·타이밍 | McDonald & Bar Or, Microsoft, arXiv:2511.03675 (2025) |
| What Was Your Prompt? | 응답 **내용 복원**(원격 키로깅) | token-length side channel | Weiss et al., USENIX Security 2024, arXiv:2403.09751 |
| PromptEcho (From Length to Content) | merged token-length로 응답 재구성 | 멀티토큰 청크 길이 | Li Sijia et al., USENIX Security 2026 **[미확인: PDF 403, 검색요약 교차확인]** |
| Time Will Tell | **출력 토큰 수**(→번역 언어·분류 클래스) | 생성 타이밍 | Zhang et al., arXiv:2412.15431 |
| LLMs Have Rhythm | **어떤 모델인지**(모델 핑거프린팅) | inter-token time | Alhazbi et al., arXiv:2502.20589 |
| When Speculation Spills Secrets | 쿼리 핑거프린팅·datastore 누출 | speculative decoding 토큰 수 | Wei et al., arXiv:2411.01076 |
| The Early Bird Catches the Leak | 시스템/타 사용자 프롬프트 | **캐시 타이밍**(네트워크 패킷 아님) | Song, Pang et al., arXiv:2409.20002 |

- **[확인된 사실]** 전통 앱/서비스 핑거프린팅(어느 앱·서비스인가)은 성숙·포화 분야
  (AppScanner, IEEE EuroS&P 2016; ET-BERT, WWW 2022, arXiv:2202.06335; 강건화 Rosetta, USENIX Security 2023).
- **[근거 기반 결론, 신중]** **네트워크 패킷 크기·타이밍만으로 reasoning 깊이(thinking-token 분량)를 분류·탐지**한
  직접적 선행연구는 확인된 범위에서 **발견되지 않았다.** 가장 근접한 것도 대상이 다르다:
  - Time Will Tell = 출력 토큰 수(추론량 아님), LLMs Have Rhythm = 모델 식별, When Speculation = speculative decoding.
  - "Stealing Reasoning Traces from Proprietary LLM APIs"(arXiv:2608.09867)는 reasoning을 다루나
    **네트워크 부채널이 아니라 애플리케이션 레이어 공격**(암호화 reasoning blob 복원).
  - **주의:** 이는 '부재 증명'이라 완전 단정 불가. "최초"라는 표현은 체계적 문헌조사 전까지 쓰지 않는다.
    신규성은 **"reasoning 깊이라는 분류 타깃이 새롭다"**로, 위 인접 연구와의 차별점을 명확히 하여 주장한다.

## 5. 문제가 될 수 있는 점 — 왜 위협인가

- **[확인된 사실]** "암호화 = 안전"은 부분적으로 거짓. 암호화 상태에서도 프롬프트 **주제**가 새는 것이 28개 LLM에서 실증됨
  (Whisper Leak, AUPRC 종종 >98%, 10,000:1 불균형에서도 고정밀).
- **[확인된 사실]** 응답 **내용의 상당 부분**도 재구성 가능(What Was Your Prompt?: 응답 27% 정확 재구성, 53% 주제 추론).
- **[연구 프레이밍]** 본 연구가 겨냥하는 '계산적 성격' 누출의 함의:
  - 프라이버시: 도청자(ISP·회사망·공용 WiFi·국가)가 내용 없이 "언제 무겁고 민감한 AI 작업을 하는지" 파악 가능성.
  - 리소스·비용 노출: 깊은 추론 = 비싼 연산 → 트래픽만으로 부하·지출 역추정 가능성.
  - 남용·이상: 자율 에이전트의 비싼 추론 남발이 트래픽에 드러날 가능성(탐지 가능 = 양날의 칼).
  - (프라이버시 항목만 선행연구로 직접 뒷받침되고, 비용·남용 함의는 본 연구가 검증할 가설이다.)
- **[확인된 사실]** 완화책은 존재하나 불완전: random padding·token batching·packet injection이
  "각각 공격 효과를 줄이지만 완전한 보호는 못 한다"(Whisper Leak 명시).

## 6. 연구 목적 [연구 프레이밍]

암호화된 LLM 트래픽에서 **내용 복호화 없이 패킷 크기·타이밍만으로 '추론 깊이'가 누출됨을 규명**하고,
그 누출이 **언제 성립하는지(인프라 경계)**를 밝힌다. 이로써 ① 암호화 시대 AI 트래픽의 새 위협 표면(프라이버시)을 드러내고,
② 그 경계 지식으로 방어(지연 균일화·패딩·배칭) 설계 근거를 주며,
③ 네트워크 워크로드 가시성·비용 추정·에이전트 남용 탐지의 토대를 마련한다.

## 7. 연구 주제 · 식별 계층 [연구 프레이밍]

'짧은 추론 vs 긴 추론' 분류는 목적이 아니라 위 누출을 증명하는 **도구**. 식별 대상을 계층으로 정의:
- L1 GenAI 트래픽 여부 / L2 서비스(ChatGPT·Claude·Gemini) / L3 출력 모달리티 /
  **L4 추론 깊이(짧은/긴 추론) ★핵심** / L5 자율성(사람 vs 자율 에이전트) / L6 보편성(환경·시점 일반화).
- 위로 갈수록 선행연구 많음(포화, §4 참조), 아래로 갈수록 미개척 — L4가 빈 땅.

## 8. 왜 '추론 깊이'인가 [연구 프레이밍 + 근거]

1. **새로운 누출 축(신규성)** — 기존은 주제·답 길이·모델 식별까지(§4). "얼마나 깊이 생각했나"는 확인된 범위에서 미개척.
2. **중요한 것들의 프록시(so-what)** — 깊은 추론 = 비싼 연산(Snell 2024가 test-time compute=성능의 핵심 자원임을 뒷받침) ·
   무거운 작업 · 자율 에이전트 활동. 내용 없이 이를 추정.
3. **사용자와 무관(강건성)** — 추론 깊이는 태스크가 정함(사용자 타이핑 습관 아님).
   기존 사용자 리듬 기반 신호보다 안정적일 것이라는 가설(대조: LLMs Have Rhythm은 모델 식별, 사용자간 리듬 편차 문제).

## 9. 연구 방법 · 설계 [연구 프레이밍]

1. **데이터 — 능동 생성**(공개셋 부재): 같은 질문에 추론 강도만 바꿔 반복 요청 → tcpdump로 요청-응답 '턴' 캡처·라벨.
2. **피처 — 순수 행동만**(내용·길이·SNI 제외): 주 신호 = pkt_gap(요청→첫 응답 침묵) + 상·하향 bytes/pkts · IAT.
3. **데이터 누수 차단**: 질문별 split(처음 보는 질문서 평가) · SNI/IP 제거 · 출력 길이 통제(길이 환원 방지).
4. **평가·확장**: 효과크기(분리도)+신뢰구간 정량화 → 서비스 일반화 → 인프라 격리로 '경계' 규명.
> 멀티프로바이더·멀티모델 확장, Task A/B/C 분리, 스트리밍 가시성 축 등 상세는 설계본 문서 참조.

## 10. 기대 효과 · 의의 [연구 프레이밍]

- **학술적**: 암호화 트래픽 누출의 새 축('추론 깊이')을 규명 + 성립 조건(인프라 경계) 특성화.
- **실용적**: 네트워크 워크로드 가시성·QoS·이상탐지 / 리소스·비용 추정 / 자율 에이전트 남용·이상 탐지의 행동 신호.
- **보안·방어**: "언제 새고 안 새나"를 알면 방어(지연 균일화·패딩·배칭) 설계 근거가 된다(공격 규명 → 방어 재료).

## 11. 향후 계획 · 로드맵 (E1~E6) [연구 프레이밍]

- E1 분류기 구축 — 패킷 피처로 짧추/긴추 분류(질문별 split)
- E2 규모·유의성 — 반복 확대로 분포·효과크기·신뢰구간 확보
- E3 서비스 일반화 — 다른 서비스에서도 되나(서비스 무관성 검증)
- E4 해상도 — 이진 → 추론 토큰 수 연속 추정(비용 추정 직결)
- E5 실현·분리 — 연속 트래픽서 턴 분리·슬라이딩 윈도우(실배포 조건)
- E6 응용 — 자율 에이전트 이상탐지 · 비용 추정
