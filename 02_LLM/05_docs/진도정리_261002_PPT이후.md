## 1. 10/2 발표가 서 있던 자리

발표자료에 들어간 것:

- 객관식 **12문항** × 3조건(`no_think` / `think_low` / `think_high`) × 3반복 = **108콜**, 이진 분류에 72회
- 답을 **A/B/C/D 한 글자**로 강제 → "길이 때문 아니냐"는 반박을 원천 차단
- 조건 간 다른 것은 추론 설정 하나뿐

그때 할 수 있던 주장: **"추론 설정이 암호화 트래픽에서 구분된다."**

그때 못 하던 것:
- 문항이 12개뿐이라 "문항 운빨 아니냐"를 못 막음
- 분석 파이프라인에 **스스로 모순되는 결함**이 있는 걸 몰랐음
- 신호가 **어디서** 나오는지 설명 못 함 (바이트가 왜 커지는지 미스터리)
- **1글자 고정**이라는 비현실적 조건에서만 측정했음

## 2. 그 뒤 한 달 — 여섯 덩어리

### (1) 3차 실험 — 규모 2.5배 ✅ 10/6

12문항 → **30문항**, 3조건 × 3반복 = **270콜**씩 세 데이터셋(Gemini / Groq 20b / Groq 120b). 에러 0건.

성능은 **유지되거나 올랐다**. 문항을 늘리면 보통 떨어지는데 안 떨어졌다는 게 요점이다.

### (2) 분석 파이프라인 결함 3건 수정 ✅ 10/27

3차 결과를 보다가 **내부 모순**을 발견했다. 가장 큰 것:

> "길이를 통제했다"고 주장하는데, **길이만 쓴 대조군이 0.966**이 나왔다.

원인 — Groq의 `completion_tokens`가 **추론 토큰을 포함**한다. 그걸 "답 길이"라고 부르면 사실상 정답 라벨을 보는 거였다. 보정 후 길이 대조군은 **majority와 완전히 동일**(분산 0)해졌다. 지금은 길이 통제가 전보다 **더 강한 형태**로 증명된다.

### (3) 신호의 정체 규명 — 두 provider가 서로 다르다 ✅ 10/6~10/27

답을 1글자로 고정했는데도 응답 **바이트**에 신호가 남는 현상을 팠다.

| | 정체 | 판정 |
|---|---|---|
| **Groq** | 응답 끝 `usage` 객체의 **숫자 자릿수**가 길어진 것 | **가짜.** 라벨의 그림자, 패딩 1바이트면 사라짐 |
| **Gemini** | 실제 데이터가 더 옴 | **진짜.** 아래 (5)에서 정체 확정 |

→ 대응으로 **보고 정본을 `timing-only`(간격 2피처)로 옮겼다.** 7개 비교 중 4개에서 타이밍 2피처가 6피처를 **이긴다**. 크기를 안 써도 잃는 게 없어서 바이트 관련 의혹을 통째로 우회한다.

### (4) 응답 길이 축 개척 ⚠️ 10/27 — 절반만

"1글자 고정은 비현실적"이라는 최대 약점을 치려고, 답 길이를 바꿔가며 측정하는 실험을 설계했다.

- **Gemini**: 완료. 길이를 풀어도 성능이 거의 안 떨어진다(3-14 → 11/3 에 3-17 로 정밀화).
  단 당시 데이터에 이미 길이 교란이 있었는데 그걸 안 가르고 결론을 냈다 — 11/3 에 다시 쳤다
- **Groq**: 쿼터 초과로 **미완**. 지금도 빈칸

삽질도 있었다. 처음엔 "1,600자 써라"처럼 길이를 고정하려 했는데, 모델이 글자수를 못 센다(준수율 0/24). 게다가 그 지시가 **추론량 자체를 5배로 늘려** 측정 대상을 오염시켰다. 길이 고정을 버리고 자유 응답으로 전환했다.

### (5) ⭐ 바이트 미스터리 규명 — 이번 달 최대 수확 ✅ 10/30~11/3

**Gemini는 추론 내용을 암호화해 숨기는데, 그 암호문의 길이를 안 숨긴다.**

정체는 `thoughtSignature` — Gemini 3 계열이 멀티턴에서 추론 맥락을 유지하려고 **내부 사고를 암호화해 되돌려주는** 값이다. 우리 파싱 코드가 "텍스트 없는 조각"이라고 건너뛰고 있었다.

```
추론 토큰 수  ──(r = 0.996)──▶  서명 길이  ──(r = 0.9977)──▶  응답 총 바이트
                                                               ↑ 관측자가 보는 것
```

**사슬이 닫혔다.** 그리고 바이트만으로 완전 분리된다:

```
추론 안 함 : 1,370 ~ 1,373 바이트   ← 폭 4바이트
추론 함    : 1,737 ~ 12,591 바이트
             겹침 0  →  AUC 1.000
```

복호화도, 타이밍 분석도 없이 **응답 크기 하나로** 갈린다.

의미: Gemini의 누출 경로가 **타이밍 하나에서 둘로** 늘었고, 둘째가 훨씬 정확하다(0.65 vs 0.996). 서술이 이렇게 된다 — **"구현이 의도적으로 숨긴 것이, 숨기는 방식 자체 때문에 샌다."**

### (6) 패딩 방어 시뮬 — 내 예상이 틀렸다 ✅ 11/3

"패딩 한 줄이면 막히니까 겸손하게 쓰자"고 생각했는데, 재보니 **비싸다**.

| 버킷 | AUC | 대역폭 |
|---|---|---|
| 512B | 0.981 (안 떨어짐) | +11% |
| 2048B | 0.944 | +46% |
| **4096B** | **0.529** | **+135%** |
| 완전 방어 | 0.500 | **+609%** |

왜 비싼가 — **동적 범위가 9.2배**(1,370 ~ 12,591)다. 버킷보다 큰 값은 계속 갈라지니까, 완전히 가리려면 **버킷 ≥ 최댓값**이어야 한다. 즉 비용이 평균이 아니라 **최악의 경우**가 정한다.

덤으로 나온 반직관 결과 두 개:
- **가벼운 패딩은 공격자를 돕는다.** 16바이트 버킷에서 순위상관이 0.883 → 0.950으로 **올랐다**. 의미 없는 4바이트 노이즈가 지워져서 신호가 깨끗해진다
- **표적 패딩이 싸지 않다.** 서명만 패딩(+145%)이 응답 전체 패딩(+135%)보다 **오히려 비싸다**. 서명이 곧 응답의 가변부라 둘이 같은 일이 된다

그리고 **패딩으로는 바닥을 못 친다** — 타이밍 채널이 AUC 0.714로 남는다. 그걸 막으려면 지연을 넣어야 하고, 그건 대역폭이 아니라 **응답속도**를 내주는 거라 비용 성격이 다르다.

## 3. 발표 숫자 갱신표

PPT에 들어간 숫자는 **2차(12문항)** 기준이다. 다음 발표에선 아래로 바꿔야 한다.

| | 2차 = PPT | 3차 = 현재 |
|---|---|---|
| 규모 | 12문항 × 3조건 × 3반복 = 108콜 | **30문항** × 3조건 × 3반복 = **270콜** × 3데이터셋 |
| Gemini `설정없음 vs high` | 0.992 | **1.000** |
| Gemini `low vs high` | 0.900 | **0.911** |
| Gemini 3클래스 | 0.733 | **0.688** ← 예측대로 하락 |
| Groq 20b `low vs high` | 0.956 | 0.927 |
| Groq 20b 3클래스 | 0.634 | **0.670** |
| 길이 대조군 | "우연 수준" | **majority와 완전 동일(분산 0)** |
| 보고 정본 | 6피처 | **timing-only(간격 2피처)** |

**3클래스 하락은 실패가 아니라 예측 적중이다.** 혼동행렬이 원인을 그대로 보여준다 — 오류가 전부 `no ↔ low`이고 `high`는 거의 안 틀린다. `think_low`의 83%가 **실제로는 추론을 0토큰 했기** 때문이다. 이건 모델 쪽 사실이지 우리 분류기 문제가 아니다.

## 4. 지금 말할 수 있는 것 / 없는 것

### ✅ 확정 (실측으로 받쳐짐)

1. 암호화 상태에서 **추론 설정이 구분된다** — Gemini 0.933, Groq 120b 0.967 (`low vs high`, timing-only)
2. **길이 때문이 아니다** — 답 토큰 수가 조건 간 예외 없이 고정, 길이 대조군 분산 0
3. 신호의 **물리적 정체**를 안다 — Gemini는 서명 길이 + 추론 전 침묵, Groq은 추론 후 침묵
4. **모델이 클수록 더 샌다** — 120b > 20b
5. **방어가 싸지 않다** — 완전 차단에 대역폭 2~6배, 그래도 타이밍이 AUC 0.714로 남음

### ⚠️ 조건부 (단서를 반드시 같이 말해야 함)

1. **AUC 1.000은 상한이다.** 다만 이유가 "1글자 고정" 때문은 **아니다**(11/3 반증).
   667자 응답에서도 바이트 AUC **0.946**이다. 상한인 건 맞지만 실전과의 거리가 작다
2. **깊이는 못 잰다.** Gemini `think_low`는 사실상 `no_think`다(추론 0토큰). 우리가 가르는 건 `low vs high`가 아니라 **"생각 스위치가 켜졌나"**
3. Groq 바이트 신호는 **가짜**다. 논문에 쓰면 안 됨

### ❓ 아직 모름

1. Groq에서 응답이 길어지면 신호가 묻히는가 (**빈칸**)
2. 추론 **양**을 연속값으로 복원할 수 있는가 (Task B 미착수 — 데이터는 이미 있음)
3. OpenAI / Claude 등 다른 provider에서도 성립하는가

## 5. 지금 돌아가는 것 / 바로 다음

### 오늘(11/3) 캡처·분석 — 완료 ✅

1글자 고정이라는 최대 약점을 치려고 **통제를 일부러 풀어서** 다시 찍었다. 각 90콜, 에러 0.

1글자 고정이라는 최대 약점을 치려고 **통제를 일부러 풀어서** 다시 찍었다.
`think_high vs no_think` 로 라벨을 맞춘 결과:

| arm | 답 중앙 | 바이트 AUC | 길이 보정 후 | 타이밍 AUC |
|---|---|---|---|---|
| `sigtest` 1자 | 1자 | **1.000** | 0.981 | 0.744 |
| `sigbrief` | 143자 | **0.971** | 0.986 | 0.997 |
| `sigfull` | 667자 | **0.946** | **0.998** | 0.827 |

**결론: 단서가 반증됐다.** 답이 667자여도 0.946이고, 답 길이를 걷어내면 **오히려 올라간다**(0.998).
답 길이가 잡음이라 그걸 빼면 서명 신호가 더 깨끗해지기 때문이다.

`free_full`에서 실제로 교란이 있긴 했다 — 지시는 똑같은데 **생각을 많이 한 쪽이 답도 37.8% 길게 썼다.**
답 길이만으로도 AUC 0.683이 나온다. 그래서 보정이 필요했고, 보정하니 서명 몫이 **80%** 로 나왔다.

⚠️ **잔차 0.998은 관측자가 쓸 수 있는 값이 아니다.** 답이 몇 자인지 알아야 계산되는데
관측자는 암호문만 본다. 성능 주장엔 **보정 전 0.946**, 메커니즘 주장엔 잔차를 쓴다. 섞으면 과장이다.

덤: **바이트가 타이밍보다 민감하다.** 약추론 9건(142토큰)에서 바이트 0.980 / 타이밍 0.656.
얕은 추론은 침묵이 짧아 타이밍에 안 잡히는데 서명은 그대로 보인다.

**8·9·10번이 세트다.** 8번(서명 발견) 혼자 두면 두 가지로 바로 맞는다 —
"1글자라서 그런 거 아니냐"(9번이 막음), "패딩하면 끝 아니냐"(10번이 막음).
셋을 떼어놓으면 안 된다.

11번은 11/3 에 새로 나온 각이다. 부채널을 "공격"이 아니라 **"감사 도구"**로 뒤집는다 —
운영자는 `effort=low` 를 걸었으니 싸게 돌았으려니 하는데, 실제로는 4~12%가 high 급으로 돌았다.
그걸 **외부에서 트래픽만 보고 검증할 수 있다.**

10번을 넣는 게 중요하다. 한계를 우리가 먼저 말하면 지적이 공격이 아니라 **우리 결론의 일부**가 된다.
