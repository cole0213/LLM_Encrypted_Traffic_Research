# 노이즈 정의·정제 파이프라인

## 핵심 요약
노이즈는 절대적이 아니라 **"이 분류 문제에 무의미/방해되는가"** 로 정의됨. 파이프라인 노이즈 규칙(De=CDN/SNI, Cc=제어, Cd=배경, DoH)을 seq meta(sni·포트)에서 직접 재현 → 원본 04 파이프라인(prism04)과 30.3% 일치로 검증. **데이터셋 성격별로 다르게**: 도메인 분류(Cipher/CSTNET)는 De 제외(SNI=정답)→노이즈 ≈0, 프로세스 분류(LAB)는 De 포함(CDN=배경)→30%. LAB 노이즈 제거로 트리 macro-F1 64.7→68.5(+4). 관련: [[앙상블 Bias-Variance·튜닝]], [[PRISM(LAB) 데이터·진단]]

## 기록

### 노이즈 규칙 파악 (X:\data-8t\00_codes\noise_rule)  <!-- (2026-08-11) -->
- 철학: 04_noise_labeling이 규칙별 원-핫으로 **마킹만**(제거 아님), 제거는 다운스트림(05_make_filelist, default_clean_rules) 선택.
- 공통 20규칙: Aa(품질) / Cc(제어: DNS·SMB·브로드캐스트) / Cd(배경: 토렌트·텔레메트리) / De(CDN/SNI: google·mail·광고) / Df(브라우저). tls1.3만 Eg_1(SNI-라벨 불일치).
- **주의**: 04 파일은 세션-스트림 추출이라 Aa(핸드셰이크/FIN)가 거의 100% 오발화(CSTNET Aa_1 100%) → 품질규칙으로 제거하면 데이터 몰살. **의미규칙(Cc/Cd/De/Df)만** 써야 함.

### 데이터셋 성격별 노이즈 정의  <!-- (2026-08-11) -->

### 규칙별 실측 제거량 (week2) — 사실상 "DNS 제거 규칙"  <!-- (2026-09-14) -->
- `lab_seqmeta_noise_basenames.txt`는 **결과 basename 목록일 뿐 규칙 표시가 없다**(생성 스크립트 `seqmeta_noise.py`가 scratchpad에서 소실). 그래서 `X:/data-8t/00_codes/noise_rule/noise_rule_all.py`의 정의로 seq meta에 **재구성**해 규칙별로 셌다. 합집합 490,146 vs 실제 파일 479,553 = **오차 2.2%** → 재구성 타당.

- **Cc_2(DNS) 하나가 29.4%. 나머지 11규칙 다 합쳐도 6.8%.** "12개 규칙으로 정제"는 과장이고, 정확히는 "DNS를 뺐고 부수적으로 11규칙이 조금 더 뺐다". Cd_2는 0건, Cd_1·Cc_4는 100건 미만 = 사실상 죽은 규칙(연구실 환경에 토렌트·SNMP 없음).
- **De 계열 4개 합 46,127(3.4%)** 중 45,088이 google/gstatic 하나.
- **실험에 실제 반영된 양은 다르다**: 목록은 seq 전체 1,354,554 기준인데 실험은 라벨 붙은 것만 쓴다 → BV 76클래스 실험에서 실제 제거 **266,193**. 나머지 ~21만은 라벨 조인 단계에서 이미 빠짐(두 필터가 크게 겹침).
- **논문에 규칙별 수치를 쓰려면 재생성 권장** — 이 표는 재구성이라 "대략 이 비율"까지만 근거로 쓸 수 있다.

### week2 전처리 퍼널 전체 (실측)  <!-- (2026-09-14) -->
```
seq 추출 원본                          1,460,213   (manifest flows_written과 일치)
 basename 중복 제거          -105,659 → 1,354,554
 라벨맵 조인 실패 제거       -476,496 →   878,058   ← 35.2%, 제일 큼
 unknown 라벨 제거             -8,265 →   869,793   [raw: 89클래스]
 파이프라인 노이즈 제거      -266,193 →   603,600   [clean: 88클래스]
 클래스 >= max(10,B=15)           -98 →   603,502   [76클래스] ← 08-30 BV 기준
```
- **week3는 라벨 조인 실패가 0**인데 week2는 35%. **라벨맵 생성 방식이 두 주차 다르다**는 뜻 — [[주차 교차전이 week2-week3]]의 드리프트(w2→w3 F1 40.99) 해석에 영향 가능(드리프트가 아니라 데이터 구성 차이일 여지).
- 클래스 필터가 `max(10, B)`라 **B를 바꾸면 클래스 수가 자동으로 바뀐다**(B=15 → ≥15 → 76클래스). 실험 설정과 데이터 구성이 커플링돼 있으니 비교 시 B 고정 필수.
- 두 "노이즈"를 혼동하지 말 것: **파이프라인 노이즈**(basename 단위, 규칙, week2 266,193 제거) vs **실앱 필터**(라벨 단위, `lab_noise_labels.txt` 75라벨, week2 470,132 = 54%). **후자는 open-set·CIL 실험에서 한 번도 안 썼다** — 희소진단에서 73→83.5로 뛰는 걸 확인해놓고 적용을 안 한 누락.
