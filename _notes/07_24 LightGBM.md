# 07_24 LightGBM

## 핵심 요약
현재 최선 기준은 목적지 정체성 45피처 LightGBM이다. 1,205피처(패킷 구조·타이밍)를 단독 또는 결합해도 LODO Top-1 정확도 이득이 없으므로, 다음 개선은 피처 수 확대가 아니라 오류 구간을 분리하고 목적지 정보의 날짜 일반화를 높이는 데 둔다.

## 기록
### 기준선과 평가 규약 정리  <!-- (2026-07-24) -->
- 최종 비교 기준: 중복 제거한 고유 실세션, DoH(`L7=DoH_DoT`)는 학습·평가에서 모두 제외, 날짜 홀드아웃으로 평가한다.
- 현재 90만 고유 실세션·88클래스 LODO에서 45피처는 Top-1 86.65%, Macro-F1 54.31, ECE 4.44다. 1,205피처 단독은 82.62%로 낮고, header 결합도 45피처를 넘지 못했다.
- `Unknown`/미분류(`__unk__`)와 희소 클래스는 학습·정확도 평가에서 제외한다. 데이터 규모 표와 평가 표의 분모를 혼동하지 않는다.
- 관련: [[45피처 vs 1205피처]], [[DoH 처리]], [[LODO]], [[정답 라벨]]

### 다음 정확도 개선 계획  <!-- (2026-07-24) -->
1. **평가 고정**: 10+11→12, 10+12→11, 11+12→10의 3개 LODO를 동일한 DoH 제외·고유 세션·클래스 규약으로 실행하고 평균/표준편차를 기준선으로 저장한다.
2. **오류 지도 작성**: 각 fold에서 `SNI 있음 / DNS만 / 둘 다 없음`, 학습일에 본 목적지/미지 목적지, 앱별 상위 혼동쌍으로 Top-1·Macro-F1·지원 수를 분해한다. 가장 큰 오류 덩어리 3개만 다음 실험 대상으로 선정한다.
3. **목적지 일반화 피처 A/B**: 기존 raw SNI·DNS·IP를 유지한 45피처에 아래를 하나씩 추가한다.
   - Public Suffix List 기반 등록 도메인(eTLD+1)
   - `SNI → DNS → IP/ASN+port` 우선순위 endpoint 키
   - IP의 ASN/클라우드·CDN 사업자 범주
   - 도메인 깊이·문자열 형태 같은 저카디널리티 피처
   새 피처는 학습일에서만 만든 매핑을 테스트일에 적용해 누수를 막는다.
4. **혼동쌍 2단계 분류**: 1단계 45피처의 상위 혼동쌍에만 후보 클래스 전용 재분류기를 붙인다. 같은 호스트의 최근 30~60초 도메인·세션 버스트를 사용하되, 배포 가능성을 위해 과거 세션 정보만 사용한다.
5. **마지막 튜닝**: 3~4단계에서 유의미한 피처 조합이 정해진 뒤에만 `num_leaves`, `min_child_samples`, `cat_smooth`, `cat_l2`를 LODO 평균 Top-1 기준으로 소규모 탐색한다. 1,205피처 전체 재추출·단독 모델은 우선순위에서 제외한다.

### 실행 순서와 판정 기준  <!-- (2026-07-24) -->
- 1차 실행: 45피처 기준선 + 오류 지도. 산출물은 fold별 지표, 오류 분해표, 상위 혼동쌍 표다.
- 2차 실행: 목적지 일반화 피처를 하나씩 추가한 A/B. 3개 LODO 평균 Top-1이 기준선보다 **0.5%p 이상** 오르고, 어느 fold도 0.3%p 이상 하락하지 않을 때만 채택한다.
- 3차 실행: 채택 피처와 혼동쌍 2단계 분류를 결합한다. Top-1뿐 아니라 Macro-F1 상승과 ECE 악화 여부를 함께 확인한다.
- 모든 대용량 CSV 로드·학습은 서버에서만 실행한다. 실행 전 서버 주 사용자에게 작업 시간·`n_jobs`·메모리 사용량을 알리고, 로컬 PC에서는 실행하지 않는다.
- 관련 코드: `03_ML/lab_dashboard_ver0.1/autolabel.py`, `03_ML/lab_dashboard_ver0.1/combine_full_compare.py`, `03_ML/lab_dashboard_ver0.1/confusion.py`
