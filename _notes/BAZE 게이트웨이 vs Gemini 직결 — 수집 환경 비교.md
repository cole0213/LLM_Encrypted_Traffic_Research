# BAZE 게이트웨이 vs Gemini 직결 — 수집 환경 비교

상위: [[02_SGS]] · 설계 본문: [[암호화 트래픽 Reasoning Effort 탐지 — 연구설계]]

> **[범위변경] 2026-11-24 — 이 경로는 본 연구(Reasoning Effort 탐지) 범위에서 빠졌다.**
> 이유 넷은 설계 노트의 "BAZE 게이트웨이를 연구 범위에서 제외"(2026-11-24) 항목에 있다.
> 요지: ① 위협모델의 성립 조건이 API 프록시를 불성립으로 못 박고 있다 ② 추론 토큰을 안 줘서
> 주 타깃 Task B 의 정답을 못 만든다 ③ 재는 대상이 모델이 아니라 중계 방식이 된다 ④ n=1 이다.
>
> **이 노트는 폐기가 아니다.** 아래 내용은 전부 그대로 참이고, "중계 구조가 바뀌면 읽어야 할
> 자리가 바뀐다"는 관찰은 독립적으로 가치가 있다. 게이트웨이 2~3곳을 재서 일반화하는
> **별도 연구**로 들일 여지를 남겨 둔다. 그때 이 노트가 출발점이 된다.

## 핵심 요약

같은 모델(`gemini-3.5-flash-lite`)을 **두 경로**로 부를 수 있다 — Google 직결과 고려대 세종 API
게이트웨이(`api.baze.co`). 둘은 키·주소·API 방언·과금이 다르고, **무엇보다 패킷에서 추론 신호가
실리는 피처가 다르다.** 직결은 `pkt_gap_ms`(첫 응답까지 침묵), 게이트웨이는 `down_iat_max_ms`
(스트림 안쪽 최대 간격). 게이트웨이가 SSE 스트림을 즉시 열기 때문이다.

이 차이 자체가 연구 결과다 — **중계 구조가 바뀌면 읽어야 할 자리가 바뀐다.** 피처 하나에
의존하는 탐지기는 경로가 바뀌면 무너진다. 이전 발표의 `ttfa-only` 대조군이 그 예다.

## 기록

### 두 경로의 정체  <!-- (2026-11-10) -->

|  | Google 직결 | 학교 게이트웨이 (BAZE) |
|---|---|---|
| 주소 | `generativelanguage.googleapis.com` | `api.baze.co/v1/gateway` |
| IP | 다수 (`172.217.x.x` 대역) | **단일 `27.96.150.173`** |
| 키 접두어 | `AIza` | `baze` |
| API 방언 | Gemini 네이티브 | **OpenAI 호환** |
| 추론 파라미터 | `thinking_config.thinking_level` | `reasoning_effort` |
| 포털 | ai.google.dev | kusllm.korea.ac.kr |

키는 **발급한 서버에서만** 유효하다. BAZE 키를 Google 주소에 던지면 `API_KEY_INVALID`(400)가
난다. 반대도 같다. 학교 키는 Google 키가 아니라 **게이트웨이 출입증**이고, 게이트웨이가 자기
upstream 자격증명으로 대신 호출한다.

- 관련 파일: `02_LLM/01_code/L4_reasoning_probe/baze_probe.py`

### 추론 설정 — 실측 사다리  <!-- (2026-11-10) -->

문항 1개(나이트 a1→h8) × 설정당 3회, 지연 중앙값.

| effort | 지연 | 판정 |
|---|---|---|
| 설정 없음 | 1,033 ms | 기준선 |
| `none` · `xhigh` · `max` | — | **400 거부** |
| `minimal` | 1,039 ms | 기준선 = 추론 안 함 |
| `low` | 1,155 ms | 기준선 ≈ 추론 거의 안 함 |
| **`medium`** | 4,624 ms | **먹힘** |
| **`high`** | 8,518 ms | **먹힘** |

`extra_body`로 넘긴 Gemini 네이티브 `thinking_config.thinking_level`은 **무시된다**(928~1,210ms).

실제로 구분되는 건 **3클래스**: `{minimal, low}` / `medium` / `high`.

직결에서도 같은 구조가 나온다 — `thinking_level=low`의 추론토큰 중앙값이 0이라 `no_think`와
구분되지 않는다(345콜 실측). **양쪽 모두 아래 단계가 뭉개진다.** 같은 모델이라 독립 증거는
아니지만, 게이트웨이가 `reasoning_effort`를 같은 thinking level로 매핑한다는 것은 보여준다.

### usage 차이 → Task 가능 여부가 갈린다  <!-- (2026-11-10) -->

게이트웨이 응답은 `completion_tokens_details: null`이다. **추론 토큰 수가 오지 않는다.**
`reason|thought|think`가 들어간 숫자 필드를 전부 뒤졌지만 없다.

| Task | 정답 라벨 출처 | 직결 | 게이트웨이 |
|---|---|---|---|
| A — Configured effort 탐지 | **내가 보낸 설정값** | 가능 | **가능** |
| B — Realized 추론 토큰 회귀 | `usage` 추론 토큰 | **가능** | **불가** |
| C — 모델 식별 | 모델명 | 가능 | 가능 |

Task A의 라벨은 `usage`에서 오지 않는다. 같은 프롬프트에 effort만 바꿔 보낸 **그 값 자체**가
라벨이다. 그래서 게이트웨이에 추론 토큰이 안 와도 Task A는 성립한다.
(1차 판정 스크립트가 이걸 묶어 "둘 다 불가"로 잘못 결론 냈다. `baze_probe.py`에서 수정.)

Task B의 Realized 라벨은 직결에서 따로 받아야 한다. 같은 모델·같은 문항이므로 문항별 추론량
측정치를 그대로 쓸 수 있다.

### ★ 신호가 실리는 피처가 다르다  <!-- (2026-11-10) -->

연기 테스트(3문항 × low/high × 1회, `out/baze_smoke.csv`) 패킷 피처 중앙값:

| 피처 | low | high | 비 |
|---|---|---|---|
| `pkt_gap_ms` | 5.6 | 5.7 | **1.02배 — 죽음** |
| **`down_iat_max_ms`** | 1,273.5 | 8,079.7 | **6.34배** |
| **`stall_total_ms`** | 1,273.5 | 8,079.7 | **6.34배** |
| `down_bytes` | 6,634 | 17,220 | 2.60배 |
| `down_pkts` | 6 | 13 | 2.17배 |
| `up_bytes` | 1,583 | 1,583 | **1.00배** |

게이트웨이가 **SSE 스트림을 즉시 연다.** 헤더가 5.6ms에 도착하므로 "요청 → 첫 응답 패킷"
간격이 추론과 무관해진다. 침묵은 사라진 게 아니라 **스트림 안쪽**, 헤더와 첫 콘텐츠 청크
사이로 옮겨간다. `down_iat_max_ms`가 그 침묵을 잰다.

분리 정도 비교:

| | 얕음 → 깊음 | 비 |
|---|---|---|
| 직결 (`pkt_gap_ms`, `gem_strict.csv`) | 842 → 1,637 ms | 1.94배 |
| **게이트웨이 (`down_iat_max_ms`)** | 1,274 → 8,080 ms | **6.34배** |

**게이트웨이 쪽 신호가 더 세다.** 단 n=3·템플릿 1개라 확정이 아니다.

**발표에 쓸 함의**: 이전 자료의 `ttfa-only` 대조군(0.958)은 게이트웨이 데이터에서 약 0.5로
무너진다. `ttfa-only`가 보는 게 정확히 `pkt_gap_ms`이기 때문이다. "왜 피처를 여러 개 쓰나"에
대한 구체적 답이 된다.

- 관련 파일: `e2_snr.py --feat down_iat_max_ms` (기본값 `pkt_gap_ms`는 게이트웨이에선 죽은 피처)
- 관련: [[암호화 트래픽 Reasoning Effort 탐지 — 연구설계]]

### 요청 크기 누출 — 양쪽 다 막혀 있다  <!-- (2026-11-10) -->

`up_bytes`가 6콜 전부 정확히 **1,583**. `reasoning_effort` 문자열 길이가 `low`=3, `medium`=6,
`high`=4로 다른데, 러너가 가장 긴 것에 맞춰 프롬프트 끝에 공백을 덧붙여 상쇄한다
(`build_conditions`). 게이트웨이에서도 그대로 작동한다.

과거 두 번 물린 같은 종류의 누출:
- `up_bytes` — `no_think`만 `thinking_config`를 안 보내 요청이 67B 짧았다 (3클래스 0.722 → 0.602)
- Groq `down_bytes` — usage 객체 토큰 수의 **자릿수** 차이 (33 → 227 → 1204), AUC 0.85~0.91

### 할당량·비용  <!-- (2026-11-10) -->

| | 직결 (무료 등급) | 게이트웨이 |
|---|---|---|
| 상한 | **일당 500콜** (모델당·프로젝트당) | **월 3,000 크레딧** |
| 분당 | 15 RPM | **120건/60초** (회원당, 키 여러 개가 공유) |
| 리셋 | 매일 (태평양 자정 ≈ 한국 17시) | 매월 1일 |
| 콜당 비용 | 0 | **약 2.44 크레딧** (200콜 487.44 실측) |
| 유료 전환 시 | $0.30/1M 입력, $2.50/1M 출력 (추론 포함) | 크레딧 추가 구매 |

직결 상한은 API 응답으로 확정:
`quotaId: GenerateRequestsPerDayPerProjectPerModel-FreeTier`, `quotaValue: 500`.

게이트웨이는 **`max_tokens` 전체를 출력한다고 보고 크레딧을 미리 예약**한다(개발자 문서).
`6010` 에러가 "잔액은 양수지만 요청 예상 비용보다 적음"일 때 난다. 우리는 `--max-tok 8192`로
보내므로 예약액이 크다. 실제 청구는 사용량 기준으로 보인다(콜당 2.44는 8,192토큰 청구가 아니다).

821문항 전수 캡처 비용 비교:
- 직결 무료: 4,926콜 ÷ 500/일 = **10일**
- 직결 유료: 약 **$18.59**
- 게이트웨이: 4,926 × 2.44 = **12,020 크레딧** → 월 한도 3,000의 4배. 불가

### 제공 모델 — Task C 기회  <!-- (2026-11-10) -->

게이트웨이가 **127개 모델**(채팅 61개)을 중계한다. OpenAI(`gpt-6.1-sol`, `gpt-6-luna`, `gpt-5.x`),
Anthropic(`claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`), Google(`gemini-4-argon`,
`gemini-3.8-flash`, `gemini-3.5-flash-lite`), xAI(`grok-4.7`, `grok-4.6`), Qwen, GLM, DeepSeek,
Solar, Kimi, Perplexity Sonar 등.

**직결보다 깨끗한 provider 비교가 된다.** 직결로 provider를 비교하면 망 경로·지리적 위치·CDN이
전부 달라서, 분류기가 추론이 아니라 **경로 차이**를 읽을 위험이 있다. 게이트웨이는 같은 IP,
같은 경로, 같은 TLS 종단이고 **달라지는 건 upstream 모델뿐**이다.

- 관련: [[STTabNet·VPN·Tor 보편분류]] (정체성 피처 배제 원칙은 같은 문제의식)

### 운영 주체 — 미확인  <!-- (2026-11-10) -->

개발자 문서와 포털 모두 "고려대학교 세종캠퍼스 API Gateway"로 제시한다. 호스트는 `api.baze.co`,
제품명은 "Baze CLI". **BAZE가 별도 회사인지 학교 조직인지 문서에 없다.**

이게 중요한 이유: "학교 망 관리자는 게이트웨이 운영자가 **아니므로** 복호화 없이 관측한다"는
연구 전제가 여기 달려 있다. 운영 주체가 학교 자신이면 그 전제가 약해진다. 도메인 이름만 보고
외부 업체로 단정했다가 철회했다. **담당자에게 직접 확인해야 한다.**

### 요청당 추가 설정  <!-- (2026-11-10) -->

- `reasoning_effort` + `tools` 동시 요청 → 400. 게이트웨이가 `reasoning_effort`를 **제거하고 재시도**
- 빈 User-Agent → Cloudflare 403 (`error code: 1010`)
- 요청 본문 25MB 상한
- 조직 보안 정책: "적용 안 함", 요청당 추가 크레딧: "없음" (요금·정책 탭)
- `temperature: 1` 강제 모델 있음 (`gpt-5`, `gpt-5-mini`, `gpt-5.1-chat-latest`, `gpt-5.2-chat-latest`)

## 아직 확인 못 한 것

- `gemini-3.5-flash-lite`의 **모델별 크레딧 단가** — 포털이 "모델 보기"로만 안내하고 수치 표가 없다
- 추론 토큰을 응답에 받는 **옵션·헤더가 있는지** — 있으면 Task B도 게이트웨이에서 된다
- `reasoning_effort` ↔ upstream thinking budget **매핑표** — 실측이 유일한 근거다
- **이용 약관** — 대량 자동 호출·연구 목적 사용·트래픽 캡처에 대한 제한. 문서에서 못 찾았다
- 게이트웨이 운영 주체 (위 참조)
