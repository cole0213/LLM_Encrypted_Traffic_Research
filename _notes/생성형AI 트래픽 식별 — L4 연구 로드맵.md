# 생성형AI 트래픽 식별 — L4 연구 로드맵

상위: [[생성형AI 트래픽 식별]] · 추천근거: [[생성형AI 트래픽 식별 — 주제 추천·의사결정]] · 문헌: [[생성형AI 트래픽 식별 — baseline 문헌분석]]

## 핵심 요약
연구 주제 = **L4 작업 단계 추론**(단순질문 vs 긴 추론 vs 도구사용)을 SNI-free·per-flow로. 학부연구생(트래픽 ML·피처·라벨링 경험) 기준, 탄탄한 베이스라인부터 시작하는 로드맵. 자기비판으로 개선한 v2(2026-09-01).

## 연구 명제 (재정의)
> ~~"단순 vs 추론 맞히기"~~ → **"출력 길이가 같아도, reasoning이 켜졌는지를 순수 트래픽(크기·타이밍)만으로 안다."**
길이로 환원되면 시시함 → 길이 통제가 설계의 중심.

## "추론 ON/OFF" 정의
- OFF = 질문 받고 바로 답 토큰 생성.
- ON = 답 전에 내부 "생각(chain-of-thought)" 단계를 거침.
- **제공자별 트래픽 흔적이 정반대 (중요):**
  - Claude extended-thinking = 생각을 스트리밍 → 답 전에 토큰이 더 많이/오래 흐름 (침묵 아님)
  - OpenAI o1/o3 = 생각을 숨김 → 요청 후 긴 침묵 뒤 답 폭발
- 라벨 소스(API): Claude `thinking` on/off, OpenAI `o1`(추론) vs `gpt-4o`(비추론).

## Phase 0 — 스코프 극단 축소
- 2-class 이진분류: **같은 질문 × reasoning ON vs OFF** (길이 환원 차단이 핵심)
- 서비스 최소, 채널 1개(API 우선), 요청-응답 **1턴**을 분류 단위로.

## Phase 1 — 데이터 수집 (새로 배우는 유일한 부분)
- 공개셋 없음 → 능동 생성 + 캡처.
- **API 우선** (ToS 안전 + 라벨 정확 + 도구사용은 tool_use 이벤트로 실제 발동 검증).
- 셋업: 스크립트로 프롬프트 전송 ↔ 동시에 `tcpdump`/tshark로 pcap. 프롬프트 전송 시각 ↔ pcap 타임스탬프 동기화로 세션 잘라 자동 라벨.
- **최소 2개 제공자**(ChatGPT/Claude, 둘 다 TCP/TLS) — 침묵형 vs 스트리밍형 추론 둘 다 관찰. QUIC(Gemini)은 나중.
- 규모: LightGBM은 클래스당 수백 OK, 딥(1D-CNN/LSTM)은 수천 필요.
- **처음부터 지킬 규칙(Sweet Danger):** 세션(flow) 단위 split · SNI/IP/포트 피처에서 제거.

## Phase 2 — 피처 정립 (강점 분야)
- 시간·크기 시퀀스 중심.
- ★ 응답 전 침묵 구간 길이 (o1형 추론 신호) + 답 전 토큰량/지속 (Claude형 추론 신호) 둘 다.
- 패킷 크기 시퀀스·방향·IAT·버스트/왕복(도구사용)·상하향 볼륨비.
- 통계요약 + 원본 시퀀스.
- 길이 관련 피처는 별도 '대조군'으로 분리(핵심 신호와 섞지 말 것).
- 시작 모델 = LightGBM(빠름·해석 쉬움·정직한 베이스라인).

## Phase 3 — 베이스라인 3단 + 정직한 평가
- 비교군: ① majority-class(최소선) → ② **길이-only 분류기**(핵심 대조) → ③ 내 피처모델.
- **내 모델이 길이-only를 이겨야** "길이 이상의 신호" 기여 성립.
- 평가: per-flow(세션) split 5-fold, 출력 길이 통제(길이 맞춘 대조), macro-F1 + confusion matrix.
- 목표 한 줄: "SNI 없이, 길이 통제하고, 추론 ON vs OFF가 되나?"

- **주 목표 이동:** 추론깊이 분류 → **자율 에이전트 남용·이상 탐지(+리소스 노출).** 추론깊이 식별(완료)은 그 핵심 신호.
- **바뀐 우선순위:** E3(서비스일반화)보다 **L5(인간 vs 자율 에이전트)를 먼저.**
- **새 실험 라인:**
  - **L5 파일럿:** 인간형 세션(희소·긴 gap·얕은추론 위주) vs 자율에이전트형 세션(밀집·짧은 gap·깊은추론 연속) 트래픽 수집·구별. 단위 = 세션(활동 창), 피처 = 요청률·gap 통계·추론밀도(=L4 신호 집계).
  - **이상탐지 프레이밍:** 정상(인간) 학습 → 자율/남용 flag (OOD/open-set = [[02_SGS]] 강점).
  - **리소스 추정:** 깊은추론 밀도 → 연산·비용 대리 추정.
- **정직 리스크:** 리듬을 우리가 부과하면 순환 위험 → 파일럿은 파이프라인 확립용, 진짜 에이전트 프레임워크(Claude Code 등) 실측이 다음. bot detection과 차별점(agentic 특유) 세워야. 프라이버시 근거(추론깊이=민감) 과장 금물.

### L5 = 2단계 (시뮬 → 진짜 에이전트)
**차이 = 리듬을 누가 만드나.**
- **1단계 시뮬 (지금, `session_run.py`):** 우리가 리듬 부과(human gap 3~14s·얕은추론 / agent gap 0.1~0.8s·깊은추론). 순환 위험 → **파이프라인 확립 + "추론밀도(frac_deep)로도 갈리나" 확인**용. 세션 단위 분류, 리듬피처 vs 추론피처 분해.
- **2단계 진짜 (다음):** 실제 자율 에이전트(Claude Code·LangChain·function-calling loop) 돌려 **스스로 만든 트래픽** 캡처. 리듬 안 부과 = authentic 증거.
  - 진짜서 자연 발생 신호(못 심는 지문): **도구 호출 다중-서버 왕복**(LLM서버+검색/코드서버), **추론→행동 loop 리듬**, 사람 gap 없음, 긴 지속.
  - 더 어려운 점: 에이전트 실셋업, 다중목적지 캡처·파싱, 세션 내부 segmentation, 비교용 인간세션.
  - **바로 가능:** Claude Code 돌리며 tcpdump로 api.anthropic.com 캡처 = 진짜 에이전트 실측.
- 관련 파일: `02_LLM/01_code/L4_reasoning_probe/{session_run,session_capture.sh,session_classify}.py`.
- 참고: [[생성형AI 트래픽 식별 — 실험 설계·평가 개념]](자율에이전트·슬라이딩윈도우), [[02_SGS]](open-world·OOD).

## ★★ 측정 중심 재프레임 (2026-09-02, 규상 연쇄비판의 수렴)
**핵심 통찰: side-channel/측정 연구는 킬러 응용이 필요 없다. 기여 = "암호화 상태에서 무엇이 새는가" 자체.**
- 규상이 "so what"(응용)을 계속 찌른 결과 → 응용(남용탐지·프라이버시)은 forward-looking·bot detection 겹침으로 약함. 반면 **측정 사실(L4 추론깊이 96% 식별)은 단단·검증됨.**
- 선행(Whisper Leak·Time Will Tell)도 "이런 게 샌다"가 심장, 응용은 곁다리.
- **재프레임:** 논문 심장 = **"암호화 트래픽으로 GenAI의 추론/작업 특성이 얼마나 읽히나"의 체계적 측정.** 응용은 동기 프레이밍이지 성패를 걸지 않음.

### "측정 확장" = 4축으로 leak-map 넓히기
"무엇이 얼마나 새는가"를 축별로 채워 지도 완성:
- **A. 무엇을 읽나(타깃):** L4 추론깊이(완료) → L3 모달리티(텍스트/이미지/음성) → L2 서비스 → 도구사용 유무 → 모델 등급. 각각 "이 속성이 트래픽에 새나, 얼마나?"
- **B. 어떤 조건서(강건성):** 네트워크(WiFi/모바일/VPN)·시점(드리프트)·방어(패딩) 하에서도 되나 → 측정의 경계.
- **C. 얼마나 세밀히(해상도):** 이진 → 순서형(low/med/high) → 연속(추론토큰수 추정). 어디까지 분해되나.
- **D. 관측 위치:** 같은 머신(앱+패킷, 완료) → 다른 vantage → passive 관찰자.
- 논문 = "추론깊이는 강하게(96%), 모달리티는 X, 서비스는 Y, Z 조건서 저하" = 체계적 side-channel 특성화.

### ⚠️ 확장은 '빈 땅 안에서'만 (규상 정정, 2026-09-02)
- **L1~L3(탐지·서비스·모달리티)는 이미 선행연구 커버됨**(음성지문·From-Prompts 텍스트/멀티모달) → 재탕 금지. (내가 "L3가 쉬운 승리"로 잘못 추천했던 것 폐기.)
- **확장은 L4(추론깊이=빈 땅)를 넓히거나 깊이는 방향만:**
  - **① E3 추론신호 서비스 일반화 [추천]:** Gemini 학습→Claude·GPT서도 되나 = "추론은 서비스 무관 행동" 증명(논지 결정타). 신규.
  - **② E4 해상도:** 이진→연속(추론 토큰수 추정). 아무도 정량화 안 함. 신규.
  - **③ L4 강건성:** 방어(패딩)·드리프트·타 네트워크서도 추론깊이 새나. Whisper Leak는 '주제'로만 방어 테스트, 추론깊이 강건성은 미개척. 신규.
- 원칙: **선행연구가 커버한 축(L1~L3)이 아니라, 검증된 빈 땅(L4)을 A(해상도)·B(강건성)·서비스일반화로 확장.**

## E3 서비스 일반화 — 핵심 발견 (2026-09-02) ★★★
**추론깊이 타이밍 신호는 실재하나, "추론시간 vs 네트워크 지터" 비율에 좌우된다 = 인프라 속도가 경계.**
- 실험: Gemini(flash-lite, 보통 GPU) vs Groq(gpt-oss-20b, LPU 초고속), 둘 다 추론 low/(med)/high × 8질문 × 3반복, tcpdump 패킷캡처.
- **Gemini(느림):** pkt_gap think_low 691ms → think_high 2154ms = **3배, 뚜렷.** (E1 분류 96%)
- **Groq(빠름):** pkt_gap low 291 · med 232 · high 318ms = **평평, 신호 소멸.** app_ttft만 미약(344→591). 코드 `groq_capture_run.py`(gpt-oss, reasoning_effort low/med/high, reasoning_format=hidden).
- **결정적 증거:** Groq high는 output_tokens 5배(48→261)=모델은 실제로 더 추론함. 근데 pkt_gap 평평 = **너무 빨리 처리해 시간차 안 남** = 속도가 죽인 것(신호 부재 아님).
- **통합 해석:** 모순 아님. 같은 원리("침묵=추론시간")의 양 끝. **side-channel 성립조건 = 추론시간 > 지터.** 느린/큰 추론서 강, 초고속 LPU서 소멸.
- **프레이밍:** "어디서나 된다"(과장) 아니라 "**언제 되고 안 되나(경계)**"를 그린 특성화 = 정직·신규. 이상탐지 응용에도 "느린 추론만 감지"로 정직.
- **혼재 주의:** Gemini(모델A·느림) vs Groq(모델B·빠름) = 모델+인프라 섞임. **못박기 = 같은 gpt-oss를 더 느린 환경(큰 모델 gpt-oss-120b or 느린 제공자)에** 돌려 "순수 속도(추론시간)가 경계"임을 격리.

### 3-way (120b 추가) — 메커니즘 vs 경계 분리 (2026-09-02)
Groq에서 모델만 20b→120b(더 큼=더 느린 추론)로 격리:
| | Gemini(느림) | Groq 20b | Groq 120b |
|---|---|---|---|
| pkt_gap low→high | 691→2154ms(3.1×) | 291→318(평평) | 274→321(거의평평) |
| app_ttft low→high | ~707→2222(3×) | 344→591(1.7×) | 364→672(**1.8×**) |
- **두 층위 갈림:** 120b도 **패킷(pkt_gap)선 여전히 평평**(지터 안), 근데 **앱(app_ttft)선 신호 살아남(1.8×, high가 ~300ms 더 걸림).**
- **통합:** 탐지가능성 = (추론지연) vs (패킷 지터). 추론시간이 지연을 만드는 건 맞음(120b app↑=메커니즘 확정), 근데 그 지연이 **지터를 넘어야 패킷서 탐지**. Gemini(~1500ms 여분)는 넘고, Groq(~300ms, 120b조차)는 못 넘어 패킷선 소멸. **인프라 속도가 천장.**
- 한계: pkt_gap 47ms차는 지터범위 → 유의성 검정 필요. 못박기 = 같은 gpt-oss를 느린 클라우드 제공자에(로컬 금지).
- **[2026-09-05] 위 "유의성 검정 필요"는 E2로 해소 → 아래 참조.**

## E2 유의성 검정 — 효과크기·신뢰구간 (2026-09-05) ★★★
기존 "96% / 평평" 점추정을 효과크기(Cohen's d)+95% 부트스트랩 CI로 승격. 코드 `e2_snr.py`(shallow vs think_high, d·CI·최적임계 오분류율). 데이터=기존 파일럿 pcap 재파싱(`out/gem_feats.csv`·`out/groq_feats.csv`, 각 72).

| 서비스 | 조건 | Cohen's d | 95% CI | 오분류율 | 판정 |
|---|---|---|---|---|---|
| Gemini | no_think vs high | **1.61** | [1.36, 2.52] | 2.1% | CI가 0 안 걸침 = **유의하게 샌다** |
| Groq 20b | low vs high | 0.42 | [-0.17, 0.89] | 39.6% | **CI가 0 포함 = 유의 X**(찍기 수준) |

- **정직한 표현 승격:** Groq는 "평평/소멸"이 아니라 정확히 **"현 표본에선 0과 구별 불가(유의한 누출 없음)"**. Gemini는 통계적으로 확실.
- **한계:** d의 pooled_std = (네트워크 지터 + 추론시간 분산) 합 → 순수 지터 아님. 순수 지터 분리는 RTT ping 베이스라인 필요(미측정). 반복 늘리면(E2 본실행) Groq CI 더 좁혀짐.
- 관련: [[생성형AI 트래픽 식별 — 실험 설계·평가 개념]].

## ★★ 길이통제 정식 실험 — 캐비엇 해소 (2026-09-23)
